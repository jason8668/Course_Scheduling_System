# 部署与维运手册

给**学校信息管理者/教学组长**的完整操作文件。系统为单校自架、纯 Web,以 Docker Compose 一键部署,六个容器(web / api / worker / worker-ops / postgres / redis)在一台主机上跑完。

> `worker` 专跑自动排课(一次可跑好几分钟),`worker-ops` 跑导出、备份、还原、寄信与定时任务。分开的用意是:**排课那几分钟里,你按「导出课表」仍然是秒回的**。

## 三分钟理解这套系统怎么跑

```
                 用户浏览器
                      │  http://校内主机IP
              ┌───────▼────────┐
              │  web (Caddy)   │  静态前端 + 反向代理 /api
              └───────┬────────┘
                      │
        ┌─────────────▼──────────────┐
        │  api (FastAPI)             │  登录、资料维护、手动排课、报表
        └───┬──────────────────┬─────┘
            │                  │
     ┌──────▼──────┐    ┌──────▼───────┐
     │ postgres    │    │ redis        │  两条工作伫列 + session 时效
     │ (你的资料)  │    └──┬────────┬──┘
     └─────────────┘       │        │
            ▲       ┌──────▼─────┐ ┌▼──────────────┐
            ├───────┤ worker     │ │ worker-ops    │
            │       │ 自动排课   │ │ 导出/备份/还原 │
            └───────┤ (可跑数分钟)│ │ 寄信/每日备份  │
                    └────────────┘ └───────────────┘
```

- **你的资料只在 `postgres`**(存于 Docker volume `pgdata`),备份档在 volume `backups`。只要这两者在,系统可随时重建。
- **worker** 只跑自动排课——它一开跑就会占住好几分钟,这是正常的。
- **worker-ops** 跑导出、备份、还原、寄信与每日自动备份。**分开的用意**:排课那几分钟正是组长最常按「导出课表」的时候,不该排在排课后面等。
- 全部跑在**一台主机**,不需要外网、不需要云端帐号,校内网路即可使用。

## 两种部署方式

同一份 `docker-compose.yml` 支援两种做法:

1. **拉取官方预建映像**(推荐,免建置、升级快):只要 `docker-compose.yml` + `.env` 两个档案,`docker compose pull && docker compose up -d`。
2. **从原始码自行建置**(想改程序、或内网无法连 GHCR 时):`git clone` 本专案后 `docker compose up -d`,首次会在本机建置映像(数分钟)。

详见 [安装指南](install.md)。

## 名词对照

| 文件用词 | 意思 |
|---|---|
| 主机 / host | 跑 Docker 的那台电脑(校内服务器、桌机、NAS 皆可) |
| 容器 container | 一个服务的执行实体,如上图六个 |
| volume | Docker 管理的资料储存区,容器删掉也不会消失 |
| `.env` | 你的设置档(密码、校名、埠号),**含机密,不要上传到任何地方** |
