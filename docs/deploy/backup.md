# 备份与还原

你的所有资料都在 PostgreSQL。系统提供三道保障:**每日自动备份**、**随时手动备份**、**还原(含还原前自动保护)**。备份档为 PostgreSQL 原生 custom 格式(`.dump`),存于 Docker volume `backups`。

---

## 一、每日自动备份(默认已开)

- `worker-ops` 容器每天 **02:00**(以 `.env` 的 `TZ` 时区为准,默认 Asia/Taipei)自动 `pg_dump` 一份。
- 默认保留最新 **30 份**,超出者由旧到新自动轮替删除。
- 可在 `.env` 调整:

  ```ini
  # 这几项为进阶设置,一般维持默认即可;如需调整可加入 .env
  # BACKUP_HOUR=2      # 每日自动备份的时(0–23)
  # BACKUP_KEEP=30     # 保留份数
  # BACKUP_DIR=/backups
  ```

  改完 `docker compose up -d` 生效。

自动备份的档名形如 `backup_20260711_020000_daily.dump`。

---

## 二、手动备份与还原(系统管理介面)

登录后到 **系统管理 → 资料备份与还原**(限系统管理员):

- **立即备份**:当场产生一份手动备份(档名 `..._manual.dump`)。重大操作(升级、大量导入、学期切换)前建议先按一次。
- **备份清单**:列出所有备份(来源标为「自动 / 手动 / 还原前保护 / 上传」),可**下载**、**还原**、**删除**。
- **上传还原**:把先前下载的 `.dump` 档上传并还原(用于换主机、异地备援回复)。非备份格式的档案会被直接拒绝,不影响现有资料。

### 还原会发生什么

1. 系统**先自动备份现状**(来源标「还原前保护」),万一还原的内容不对可再退回。
2. 以该备份**覆盖整个资料库**。
3. 还原完成后**强制所有人重新登录**(因为用户资料已被替换)。你会被导回登录页,以还原时点的帐密登录。

> 还原是覆盖性操作,请确认选对备份档再执行。有「还原前保护」这道自动备份垫底,误操作仍可救回。

## 三、异地备援(强烈建议)

Docker volume 存在同一台主机。**若主机硬碟坏掉,volume 一起没了。** 真正安全的备份要放到另一个地方:

### 做法 1:定期下载备份档(最简单)

到「资料备份与还原」按「立即备份」→「下载」,把 `.dump` 档存到另一台电脑、外接硬碟或云端硬碟。要复原时在新主机上「上传还原」。

> **超大资料库的还原走这里,不要用网页上传。** 系统对网页上传有 200MB 的请求体上限(避免超大上传打爆主机记忆体)。若贵校资料库的 `.dump` 超过此上限,请改用下方「做法 2」的 volume 复制法把备份档放回容器,再从系统介面「还原」。

### 做法 2:把 backups volume 同步到外部(可排程)

备份档实际存在 volume `backups`。可用命令把整个备份目录复制到主机档案系统,再由你既有的异地备份机制(rsync、NAS 排程、云端同步)接手:

```bash
# 把容器内 /backups 复制到主机当前目录的 ./backups-export
docker compose cp worker:/backups ./backups-export
```

反向(把外部备份档放回系统以便还原):

```bash
docker compose cp ./某份.dump worker:/backups/
```

放回后即会出现在「备份清单」中,可直接还原。

## 四、手动用命令备份 / 还原(进阶)

若你偏好在命令列操作(例如写进自己的排程脚本):

```bash
# 备份(pg_dump 在 worker 容器内执行,worker 才装了 postgresql-client)
docker compose exec worker pg_dump -Fc -h postgres -U scheduler -d scheduler \
  -f /backups/manual_$(date +%Y%m%d_%H%M%S).dump

# 还原(会覆盖现有资料;跨版本可能出现可忽略的警告,资料仍正确)
docker compose exec worker pg_restore --clean --if-exists --no-owner --no-privileges \
  -h postgres -U scheduler -d scheduler /backups/某份.dump
```

> `PGPASSWORD` 于容器内已由 `.env` 提供,通常无需另外指定。通过系统介面操作会多做「还原前自动备份 + 强制重新登录」,命令列方式不会,请自行留意。

## 常见疑问

**Q:备份含哪些资料?** 全部业务资料(学期、教师、班级、课表、请假、代课、通知、稽核纪录、系统设置与帐号)。不含 Redis(仅伫列与 session 时效,可重建)与上传档暂存。

**Q:换一台新主机怎么搬?** 新主机照[安装指南](install.md)装好、起好空系统 → 系统管理上传旧主机下载的 `.dump` 还原,即完成搬迁。

**Q:备份会不会拖慢系统?** `pg_dump` 对线上资料库影响很小,且自动备份排在凌晨。手动备份亦为秒级(视资料量)。
