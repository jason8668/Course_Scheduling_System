## 工程改善(原「v1.3 范围」;v1.3.0 改做单双周后顺延,内容与顺序不变)

排序原则:**学校装得快、用得顺的先做**,纯工程卫生的后做。全部不改资料表结构。

**开工时机**:由专案负责人决定;先让使用学校实际用 v1.3.0 几天,没有新的问题回报再动工。

### 1. api 映像拆掉 ortools —— M

- **现况**:`ortools` 在 `pyproject.toml` 主依赖,api 映像 **674MB**;排课求解只在 worker 跑,api 容器用不到。
- **影响谁**:第一次安装与每次升级的学校。校内网路或 NAS 拉映像慢,是「升级很麻烦」的主因之一。
- **做法**:移到 `[solver]` 之类的 extra 由 worker 安装;确认 api 端没有任何路径导入 `ortools`
  (pre-flight 检查若有用到要拆开)。预期 api 映像约 200MB。
- **验证**:api 容器内 `python -c "import ortools"` 应失败、全部 API 与 e2e 照常;worker 自动排课照常。

### 2. 前端改按需导入 Naive UI —— M

- **现况**:`main.ts` 以 `app.use(naive)` 全量注册,主程序 **1.4MB**。校内网冷载约 1 秒,可接受但偏大。
- **做法**:移除全量注册,改各页自行导入(多数页面已经是具名导入);检查是否有模板直接用未导入的元件。
- **验证**:建置后主程序大小、冷载时间(`perf-page-load.spec.ts`);**e2e 全跑**——漏导入的元件只会在执行时才坏。

### 3. 科目导入支援「主科」栏 —— S

- **现况**:表单可勾「主科」(`is_major`,影响自动排课把主科排在上午),但 Excel 导入没有这一栏,
  导入后要一科科手动勾。
- **做法**:导入范本加「主科」栏(是/否),导入时写入;旧范本没有这栏照样可导入。

### 4. 配课 API 直接挡群组节数不一致 —— S

- **现况**:跑班群组成员节数不一致时,要等到自动排课前的 pre-flight 才挡(`group_shape_mismatch`)。
- **做法**:建立/修改配课当下就回 409 并说明是哪几门课不一致,错误提早出现在组长正在填的地方。

### 5. 还原上传改串流落地 —— S

- **现况**:`restore-upload` 以 `await file.read()` 整包读进记忆体;Caddy 200MB 上限与「超大资料库走 volume 复制」
  文件已缓解,但 4GB 主机上仍有风险。
- **做法**:分块写入暂存档再验魔数、交给 worker 还原。

### 6. CORS 设置文件化与格式验证 —— S

- **现况**:`cors_origins` 本来就能用环境变数(JSON 格式)覆写,但没有文件、格式错了也不会提示。
  同源部署(默认)下无实害。
- **做法**:部署文件补一段;设置格式错误时启动即明确报错。

### 7. 工程卫生 —— S

- `tests/solver/test_purity.py` 目前只扫绝对导入(`level == 0`),补相对导入。
- `slots_overlap`、`course_key` 补边界单元测试。

## 等使用学校回馈再决定

- **教师端「我的课表」显示调课**:调课成立后,教师自己的课表不会反映这次变动(看板、通知、调课单都有)。
  使用学校目前以纸本调课单通知,没有提出需求。
- **调代课处理页的清单很长时**:研习多的周,一张假单可能十几节。目前逐节处理;若回馈操作太多,
  再考虑「整张假单一次调课」。

## 工程改善之后(明确延后,不是忘记)

- **完整清单分页**(UI + offset):调代课纪录、请假清单目前取最新 1000 笔并明讲被截断;整年资料变慢时再做。
- **还原溯源 `restore.log` + stale 警告持久徽章**:presafe 档名时戳暂可佐证。
- **求解前 hard-only 探测 + warm start;部分排课独立短时限**:解质量/速度优化,独立可做。

## 单双周的后续(v1.3.0 刻意不做)

- **跑班群组＋单双周**(例如单周社团、双周班会):两种「绑在一起排」的机制叠加,复杂度与风险最高;
  目前没有学校提出,等有需求再评估。
- **Excel 导入配课支援单双周**:需要新的范本栏位(单周/双周、配对),且要与旧范本相容;
  单双周课每校通常只有几组,先在界面上建。可排 v1.3.x。

## v2(需要外部条件)

- **LINE 通知 adapter**:走 LINE OA Messaging API,各校自申请 channel token + 绑定码流程。
  等有试用学校提出需求再做——没有真实 OA 可测之前,写了也验不了。
- **软约束权重 UI**:`GET/PUT /api/solver/config` 已在,滑杆是给进阶用户的;等有学校真的想调权重再开工。

## 刻意不做(除非出现真实个案)

- **「一门课逐节换教室」**:现行一门课整学期一间教室,符合台湾中学实务;改成逐节换教室是为了不存在的需求付模型复杂度。
- **`teacher_time_rule` 墙钟化(加节次表维度)**:v1 已定案「以该配课班级的节次表解读」,单节次表学校(绝大多数)无此问题。
- **没有请假的教师互调**:使用学校的调课几乎都由研习引起,研习登记为公假/进修后走既有调课流程即可(2026-09-17 确认)。
- **自动升级**:新版本提醒只提醒;升级必须由学校先备份、自己决定。
